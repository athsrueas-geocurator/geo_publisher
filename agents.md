## Record important discoveries

- Original question/program links were generated with keyword matching and a fallback to the first initiative; review every edge before copying it. Question Answers target Answer entities, not evidence Claims. Follow [question reconciliation](docs/original-question-reconciliation.md); preserve questions separately from propositions and do not import template-generated assessment bounds as statistics.

- The [Krueger–Hanushek review](docs/class-size-debate-publication.md) records version-specific citation rules, exact-case-insensitive GraphQL equality (`isInsensitive`), and why checkable author-model outputs need Is factual=true while interpretive policy positions remain nonfactual. Preserve model/experiment distinctions and avoid treating differently scoped positions as logical opposites.

- Separate source-content review, payload/index equality, governance execution, bounty indexing and rendered review. Passing one does not imply the others. See [publication review](docs/geo-publication-review.md). Read source data at runtime; do not generate new study/catalog scripts with chains of text substitutions.

- Education research must support linked debate Claims, not only standalone estimate records. Follow [the debate-claim design](docs/education-debate-claim-design.md): distinguish policy propositions from checkable findings; use verified Related claims, Supporting arguments and Opposing arguments with adjudicated direction and rationale. Existing estimates supply evidence through their stable IDs. Never inflate evidence by counting alternate statistical representations as independent studies, force opposition, or treat popularity as truth. Numeric detail is essential on estimate Claims; a policy Claim instead needs a clear scope and linked evidence, without pretending the policy judgment was a published experimental result.

- For study metrics, distinguish source-reported observations, source-reported models, and local diagnostic calculations. Preserve approximate qualifiers and cite exact source locations. Do not publish diagnostic recalculations as study findings or silently replace the authors' figures; keep these checks local unless the user explicitly requests a separately labeled derived analysis. Unreconciled author models must not enter a computed cost-effectiveness ranking.

- Published entity descriptions must be at most two concise sentences. Put extended definitions, assumptions, methods, caveats and source discussion in labeled content blocks, while retaining numeric facts and relations as structured properties. Audit existing published records when correcting a recurring presentation mistake. Do not copy operational instructions into reader-facing descriptions or blocks.

- A Claim must express a source-backed proposition, not a table-row label or research topic. Before publishing, read its title and description without the table: the finding, relevant magnitude/unit, intervention or comparison, population/study and period must be understandable, with uncertainty and the paper's interpretation preserved. Never use generic descriptions that merely promise attached estimates. Geo's dedicated Claim page hides ordinary numeric fields and may hide blocks, so essential meaning must be visible in the title and concise description; verify that page as well as the dataset table. See `docs/education-description-guidelines.md`.
- Treat Claim readability as a separate acceptance check from numeric accuracy and table rendering. Record which source-backed Claims were actually reviewed and repaired; a heuristic audit nominates review and does not certify either flagged or unflagged records. When fixing a generated wording defect, fix the generating template too, preserve published IDs, and verify a dedicated Claim page. Keep outstanding study families explicit in `todo.md`; do not describe a partial repair as a completed global pass.

- Whenever work reveals an important fact, failure mode, correction, constraint, or reusable technique, record it in a relevant `.md` file during the same task. Do not leave durable knowledge only in chat.
- Put the note in the folder relevant to the discovery: alongside the affected code or dataset for local concerns, or under `docs/` for cross-cutting SDK, API, ontology, publishing, and rendering guidance. Update an existing relevant file rather than creating duplicate notes; otherwise create a clearly named Markdown file.
- Record what was observed, the date, supporting evidence or source links, its practical implications, any verified fix, and remaining uncertainty or follow-up work. Distinguish verified behavior from assumptions and proposals. Never include credentials or other secrets.
- Link broadly useful notes from `agents.md` or the relevant folder's guidance, and add actionable unfinished work to `todo.md`. When later evidence changes a finding, update the note and clearly supersede stale conclusions.

## Geo API tooling guidance

- Save generated TypeScript/JSON and publication text as UTF-8. The education submission guard rejects C1 control characters and Unicode replacement characters before new signing; repair the generator and rebuild validation instead of bypassing it. See [encoding findings](docs/education-text-encoding.md). Preserve already-submitted payloads/journals and distinguish copy repair from source-content verification.

- Store DOI property `7cb59354e30c48119e99ff62fcf61646` as a full `https://doi.org/10.…` resolver URL. Geo's browser renderer can interpret a bare DOI as an IP-address URL. Preserve the identifier exactly; normalize the optional resolver prefix when comparing identities. The education submission path rejects new bare-DOI writes without mutating payloads or interfering with reconciliation of already-submitted transactions. See `docs/impact-reconciliation.md` for the verified correction and bibliography-wide audit.

- If a source URL fails or times out, search for the official current landing page or an equivalent authoritative copy. Verify title, authors, year, DOI/report number and version before accepting the replacement; preserve the original URL and replacement evidence in the reconciliation notes. A failed Geo search query is not a broken source URL, and neither failure proves an entity is absent. User instruction confirmed 2026-09-12.

- Numeric display findings are tracked in `docs/geo-number-formatting.md`. Keep numeric values typed; use verified property Format metadata for percentages. Legacy Health formats such as `0.0%` can fall back to raw numbers in the current frontend. Fraction-valued rates require explicit scaling in the ICU format. Record new SDK/API/rendering issues and their evidence in the relevant diagnosis document.

- SDK runtime is pinned to `@geoprotocol/geo-sdk@0.20.3` (npm latest verified 2026-09-11). Use the installed SDK API and release notes alongside the Geo Explorers skills. Prefer `Ops.textBlocks.create` / `Ops.dataBlocks.create` with persistent IDs for new migration blocks. The skills submodule now tracks `geo-explorers/content-management`, checked out at `a2f9a15` on 2026-09-11.
